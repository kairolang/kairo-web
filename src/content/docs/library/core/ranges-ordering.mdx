## `Ordering`

```kairo
enum Ordering derives i8
```

The result of a three-way comparison: what `a <=> b` evaluates to.

The discriminants are -1, 0 and 1. The relational operators are lowered from `op <=>`:
`a < b` becomes `((a.op<=>(b)) as i8) < 0`, with the original token compared against 0.

**Example**

```kairo
struct Version { var major: i32 }

extend Version {
    fn op <=>(const self, const other: Version) -> Ordering {
        if self.major < other.major { return Ordering::Less }
        if self.major > other.major { return Ordering::Greater }
        return Ordering::Equal
    }
}

fn main() -> i32 {
    var a = Version { major: 1 }
    var b = Version { major: 2 }
    if (a <=> b) == Ordering::Less { return 0 }
    return 1
}
```

### `Ordering.Less`

```kairo
Less
```

The left operand orders before the right (-1).

### `Ordering.Equal`

```kairo
Equal
```

The operands are equivalent (0).

### `Ordering.Greater`

```kairo
Greater
```

The left operand orders after the right (1).

## `Range`

```kairo
struct <T> Range
```

A bounded range: `a..b` (exclusive end) and `a..=b` (inclusive end).

Field order is evaluation order: RangeLowering builds a range as a designated initializer, and
C++ evaluates those in declaration order, so `f()..g()` runs `f` first. Keep `begin` before
`end`. A `for` loop over a range is lowered to a counting loop directly and never builds one.

**Example**

```kairo
fn main() -> i32 {
    var sum = 0
    for i in 0..4 { sum += i }
    return sum - 6
}
```

## `RangeFrom`

```kairo
struct <T> RangeFrom
```

A range with no end: `a..`, or `..` as `begin: 0` (a `RangeFrom<usize>`).

Only valid as a subscript index, such as `v[2..]`.

## `RangeTo`

```kairo
struct <T> RangeTo
```

A range with no start: `..b` or `..=b`.

Only valid as a subscript index, such as `v[..3]`.
