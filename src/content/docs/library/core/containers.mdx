## `Hash`

```kairo
interface Hash
```

The requirements for a `{K: V}` / `{T}` key: a hash and an equality consistent with it.

If `a == b` then `a.hash() == b.hash()`. Hashes are deterministic: no per-process seed, so a
map's layout is the same on every run. The primitives, pointers and `string` conform out of the
box; a key type conforms like any type conforms to an interface (its own members, an
`extend X impl Hash`, or structurally). `other` is `const`, so comparing two keys copies
neither.

### `Hash.hash`

```kairo
fn hash(const self) -> usize
```

Returns the key's hash, to be folded into a table slot by the container.

### `Hash.op ==`

```kairo
fn op ==(const self, const other: Self) -> bool
```

Returns true when the keys are equal; must agree with `hash`.

## Hash implementations for primitives

Each primitive type implements `Hash` as follows.

| Type | How it hashes |
| --- | --- |
| `bool` | `true` and `false` hash as 1 and 0 through `mix64`. |
| `u8` | Unsigned integers (and `char`) hash through `mix64` of their value. |
| `u16` | Unsigned integers (and `char`) hash through `mix64` of their value. |
| `u32` | Unsigned integers (and `char`) hash through `mix64` of their value. |
| `u64` | Unsigned integers (and `char`) hash through `mix64` of their value. |
| `i8` | Signed integers hash through `mix64` of their value sign-extended to 64 bits. |
| `i16` | Signed integers hash through `mix64` of their value sign-extended to 64 bits. |
| `i32` | Signed integers hash through `mix64` of their value sign-extended to 64 bits. |
| `i64` | Signed integers hash through `mix64` of their value sign-extended to 64 bits. |
| `usize` | Pointer-sized integers hash through `mix64` of their value widened to 64 bits. |
| `isize` | Pointer-sized integers hash through `mix64` of their value widened to 64 bits. |
| `char` | A `char` hashes through `mix64` of its value. |
| `u128` | A 128-bit integer hashes as `fold_mul` of its two 64-bit halves. |
| `i128` | A 128-bit integer hashes as `fold_mul` of its two 64-bit halves. |
| `f32` | A float hashes through `mix64` of its bit pattern, with `+0.0` and `-0.0` hashing alike. A NaN compares unequal to everything, itself included, so a NaN key can be inserted but never found again. Do not key a map by a float that may be NaN. |
| `f64` | A float hashes through `mix64` of its bit pattern, with `+0.0` and `-0.0` hashing alike. A NaN key can be inserted but never found again; see the `f32` conformance. |

## `HashMap`

```kairo
class <K impl Hash, V> HashMap
```

Hash map from `K` to `V`. `{K: V}` desugars to `HashMap<K, V>`, and `{k: v, ...}` builds one.

Entries are stored densely in insertion order, so iteration order is deterministic. Lookup,
insert and `erase` are O(1) expected; `erase_ordered` is O(n). K must implement `Hash` (a
`hash()` method and `==`).

Inserting or erasing invalidates every pointer from `find` / `get` / `begin` / `[]` and must
not happen during `for ... in m`. A copy is a deep copy.

**Example**

```kairo
var m: {i32: i32} = {}
m[1] = 10
m.insert(2, 20)
var found = false
if let v = m.get(2) { found = (*v == 20) }
```

**See also**

HashSet


Creates an empty map. Allocates nothing.

### `HashMap.HashMap`


V must be default-constructible (each value is assigned after the entry is created).

## `HashSet`

```kairo
class <T impl Hash> HashSet
```

Hash set of `T`. `{T}` desugars to `HashSet<T>`, and `{a, b, ...}` builds one.

Elements are stored densely in insertion order, so iteration order is deterministic. `insert`,
`contains` and `erase` are O(1) expected. T must implement `Hash`. The mutation and
invalidation rules are HashMap's: do not insert or erase during iteration.

**Example**

```kairo

s.insert(2)
var n = s.size()
```

## `Slice`

A non-owning view over `len` contiguous elements. `[T;]` is `Slice<T>`, and a `[...]` literal

## `Vector`

```kairo
class <T> Vector
```

Growable, owning, contiguous array. `[T]` desugars to `Vector<T>`, and the list literal
`[a, b, c]` against a `[T]` target builds one.

Elements live in one heap block from the allocator in effect. Indexing, `front`, `back` and
`pop_back` check bounds and trap (see \panics on each); growth is geometric (twice the
capacity, at least 4), so `push_back` is O(1) amortized. A copy is a deep copy; a `[MoveOnly]`
has no copy and no `Vector(n)` / `resize(n, value)` (those members need T to be copyable /
default-constructible).

References and pointers into a vector (`v[i]`, `begin()`, `data()`) are invalidated by any
operation that grows, inserts, erases or clears.

**Example**

```kairo
var v: [i32] = [1, 2, 3]
v.push(4)
var sum: i32 = 0
for x in v { sum += x }
```

**See also**

Slice
