Attribues are a powerful feature in Kairo that allows you to modify the AST of your code. They are similar to macros, but they are a lot more powerful and flexible. They can be used to generate code, modify existing code, or even remove code.

| Garantees | Check |
| --- | --- |
| Type Safety | Yes |
| Hygiene | Yes |
| Scope | Yes |
| Expansion Time | Compile Time |
| Expansion Order | Inner to outer |
| Expansion Context | The item they are attached to |

One thing about attributes, they must keep the node the same, attributes can not return new nodes, they can only modify the existing node. This is to ensure that the expansion process is deterministic and that the AST remains consistent throughout the expansion process. If you want to create new nodes, you can use the `std::create` function to create new nodes and then modify the existing node to include the new nodes.
This is also a security feature, as it prevents attributes from completely changing the structure of the code and potentially introducing security vulnerabilities.
Attrbute definitions can be overloaded based on node type or args.

# Defining Attributes

```kairo
import std::AST

macro @my_attr(node: *AST::FunctionDecl) {
    node->name = "my_attr_" + node->name
    node->body.append(
        AST::parse!(std::println("Hello from my_attr!"))
    )
}
```

# Using Attributes

```kairo
@my_attr
fn my_function() {
    std::println("Hello, World!");
}
```

after expansion, the code will look like this:

```kairo
fn my_attr_my_function() {
    std::println("Hello, World!");
    std::println("Hello from my_attr!");
}
```

# Attribute Arguments
Attributes can also take arguments. For example:

```kairo
macro @repeat(block: *AST::Block, times: i32) {
    var old_block = block->clone()
    var new_block = std::create<AST::Block>()

    for i in 0..times {
        new_block->body->append(old_block)
    }

    *block = *new_block
}

@repeat(3)
{
    std::println("Hello, World!");
}
```

after expansion, the code will look like this:

```kairo
{
    {
        std::println("Hello, World!");
    }
    {
        std::println("Hello, World!");
    }
    {
        std::println("Hello, World!");
    }
}
```

Attributes can be attached to any ast node as per the full ast spec (NOT yet defined).

Expansion order is inner to outer, meaning that if you have nested attributes, the innermost attribute will be expanded first. This allows you to create complex code transformations by combining multiple attributes.

```kairo
@deserialize  // runs on the result of @serializable
@serializable // runs on the class definition
class Foo {
    var x: i32
}
```
