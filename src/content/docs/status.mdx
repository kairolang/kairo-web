# Implementation Status

The language reference describes Kairo as designed. This page lists where the Stage 1 compiler, the first alpha, falls short of it. Each entry is removed when the gap closes.

Stage 1 is built from source for now; prebuilt downloads come with the first release. See [Installation](/docs/install/).

---

## Not Compiled Yet

| Feature | Status | Meanwhile |
|---|---|---|
| Vector literals (`var v: [i32] = [1, 2, 3]`) | Type-check and compile, but do not link: the built-in vector constructors are not implemented yet | Use an array `[T; N]` or a slice `[T;]` |
| Set literals `{a, b}` | Not compiled | - |
| Map literals `{k: v}` | Not compiled | - |
| Initializing a `const` field or a [field without a default](/docs/language/classes/#fields-without-a-default) in a constructor | Compiles. Not yet ([SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported)): in a generic constructor or one with an expression body; with `try`, `finally`, an `inline` block, `label!` or `jump!` before the last such initialization; with a `static` or array local declared before it and used after it; an array field of arrays, or of a generic length | Move that code after the last initialization, or give the field an initializer |
| Non-generic payload enums whose payload has a type with unknown copy, move and destruction (`enum W { Has { b: Box<i32> } }` for a generic class `Box`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Make the enum generic over the payload type |
| Associated types (`type Node` in an interface) | Parsed, with bounds and defaults; not compiled yet (`Self::Node` and `T::Node` don't resolve, and conformers don't supply them) | - |
| Virtual interfaces (`virtual interface`, calls through `*Iface`) | Not compiled yet | Dispatch through a base class with `virtual` methods |
| Shorthand `.V` as the LEFT operand of `==` / `!=` (`.North == dir`) | Rejected with [SC123E](/docs/language/diagnostics/#sc123e-a-variant-name-does-not-fit-the-expected-type) | Put the variable first: `dir == .North` |
| An initializer on a `static` array-typed field, on a field that is an array of arrays, or one that is not a list literal (`[a, b, c]`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Initialize it in a constructor (`self.a = [...]`), or write the list literal |
| A generic record's field default that reads another field (`class <T> G { var a: i32 = 1  var b: i32 = a + 1 }`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Repeat the value instead of reading the field |
| Struct destructuring (`var {a, b} = s`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Read the fields one by one: `var a = s.a` |
| Functions, classes and enums declared inside a function body | Not compiled yet (a local `struct` works) | Declare them at file scope |
| In a [script](/docs/language/modules/#scripts): a top-level variable of nullable type whose initializer is not a constant (`var g: i32? = find()`), and top-level destructuring (`var (a, b) = pair()`) | Rejected (`... is not supported yet`) | `var g: i32? = null`, then `g = find()` on the next line; destructure inside a function |
| Top-level statements in an imported module (module initialization) | Rejected: only the file the program starts from runs top-level statements | Put the code in a function and call it from the script |
| `for ... in` over Kairo vectors, sets, maps and strings | Not supported yet | Loop over a slice, an array or a range |
| Yielding a literal from a generator (`yield 7`) | Fails in the C++ step | Yield a variable: `var v = 7` then `yield v` |
| `eval for` directly in a `module` or class body | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Use an `eval for` in a function body |
| In an `eval for`: a label (`outer: eval for ...`), a `return` of a class or struct value from inside the loop, and iterating an array whose length is a generic value parameter | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Return after the loop |
| An `eval if` branch that is valid only for some instantiations of a generic (`eval if typeof T == i32 { return int_to_bytes(value) }`, the [Type-based branching](/docs/language/eval/#type-based-branching) example) | Both branches are type-checked against the bounds, so the example does not compile; this waits on per-instantiation checking of generics | Use [overloads](/docs/language/functions-overloading/) |
| Vectors, sets, maps and f-strings at compile time (`eval V: [i32] = [1, 2]`, `f"n={n}"` in an `eval fn`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Use an array; string literals, integers, floats, `bool`, `char`, arrays and tuples are evaluable |
| An `eval` field computed by an `eval fn` used as an array length in a field of its own class (`class B { eval J = two()  var b: [i32; J] }`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported), with a fix-it moving the constant to module scope (where, computed by a call, it is not yet accepted in a field's type either: see below) | Make the constant fold (literals and arithmetic over `eval` constants) |
| A generic value parameter of a type other than an integer or an [eval class](/docs/language/generics/#eval-classes-as-value-parameters) (`<eval B: bool>`, `<eval F: f64>`) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | Use an integer parameter |
| A string literal written directly in an eval class value argument (`Widget<Config(4, "small")>`) | Rejected (`... must be computed at compile time`) | Bind it first: `eval SMALL = Config(4, "small")`, then `Widget<SMALL>` |
| A generic class's `requires` predicate that names an `eval` constant or `eval fn` (`class <T> B requires sizeof T <= LIMIT`) | Accepted and not checked (a predicate of the class's own parameters, literals and `sizeof` is checked) | Write the limit as a literal in the class's clause, or check it in a constructor's `requires` |
| An array length or generic value argument computed by an `eval fn` call, or from an `eval` constant whose initializer calls one, in a declaration's type (a field, a parameter or return type, a file-scope variable: `var a: [i32; size()]` in a class) | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) (inside a function body it is accepted) | Declare the array inside the function, or make the constant fold (literals and arithmetic over `eval` constants) |
| `await`, `spawn` and the `thread` expression (`thread work()`) | Can be declared as operators, but do nothing yet. (A [`thread` variable](/docs/language/variables/#thread-local-variables) is a different construct and is compiled.) | - |
| [Panic](/docs/language/panic/) (`panic`, `try`/`catch`/`finally` around a panicking call, the C++ view `::builtin::value_or_throw`) | Compiled and run. Panic sets are inferred and checked, as specified: unhandled calls, declared sets and where they are required, the subset rules for overrides, conformers and function types, `main`, `panic` with `-> !`, constructors and destructors (which never panic), the error-type rules, and `try`/`catch` arms (dead, duplicate, after a bare `catch`); an expression arm may `return`, `break` or `continue`. A panicking function returns its error as a value (no unwinding): propagation, both `try` forms, re-panic (keeping the original site), `finally`, `where` groups, closures and function values work, in registers up to 16 bytes. Not supported ([SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported)): panics in generic functions, generators and `async` functions; a call of a panicking operator; keeping a bare `catch e` binding in another variable. The [C++ view](/docs/language/c-cpp-exceptions/#the-value-api) works through `#include "foo.k"` and `--emit-headers`: the inspection helpers, `value_or_throw` and `what()` (from `op panic`, a type's own or an `extend`'s), and a header declaring `[[nodiscard]] Panic<T, E...>`. A [C++ exception arm](/docs/language/c-cpp-exceptions/#c-to-kairo) (`catch e: cxx::std::exception`) works in both `try` forms. The source location in `what()` and `::builtin::site()` is found on ELF (Linux, the BSDs) only so far: elsewhere `what()` gives the type without a location. An `extend` of a generic type supplying `op panic` is not used by `what()`. `crash!()` and the asserting downcast `p as *D` (a crash on a miss) work | Without a location, log `::builtin::type_id<E>` |
| [Variadic enums](/docs/language/enums-adt/#variadic-enums) (`enum <T, ...E>`, pack-expanded variants `V { ... }...`) and [generic variadic functions](/docs/language/functions-parameters/#generic-variadic-functions) | Compile: pack parameters, forwarding with `...`, `for` over a pack, packs in class and base arguments, and pack-expanded variants built and matched by payload type. Not yet ([SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) or a not-viable call): writing a pack's types as generic arguments (`f<i32, bool>(...)`), a pattern over a pack (`Box<T>...`), a pack-expanded field typed other than the pack itself (`e: *E`), building or matching a pack-expanded variant in a generic function, and a `return` from inside a `for` over a pack in a function whose return type has no default constructor. A partial specialization whose pattern holds a pack (`Traits<Box<T>, Args...>`) is ignored | Pass the types through arguments; build and match the variant where its type is concrete |
| The checked `as` into a [closed enum](/docs/language/enums-plain/#closed-and-open-enums), and `unwrap!()`, in a file-scope initializer (`var c = f() as Color` outside a function) | Fails in the C++ compiler ("statement expression not allowed at file scope"); a constant operand is checked at compile time and works | Initialize the variable from a function, or with a constant |
| `n as E?` from an integer into a nullable plain enum | Fails in the C++ compiler | Assign `n as E` to an `E?` instead |
| `@unwind` on a closure | Rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) (it parses as an expression attribute) | Use a named `@unwind` function, or build with `-funwind` |
| Attributes on expressions, including heap allocation with `@create T(args)` | Parsed; rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported) | - |
| [`where` guards](/docs/language/where/) on functions | Compile on free functions and methods (methods of generic classes too), with the fallback, priority order, coverage and the unreachable / overlap warnings. Not yet ([SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported)): on a generic function, a `virtual` or `override` method, an `extend` member, an operator or constructor, an out-of-line method definition, a forward declaration, a generator, an `async` function, a variadic function, or an overload with default arguments. An `unsafe` overload beside them is rejected (R039E): unsafe overloads cannot coexist with safe ones yet | Test the condition with an `if` inside one function |
| [`typeof`](/docs/language/type-system/#typeof-identity-semantics), as a type (`var y: typeof x`) or as a value | The compiler crashes (an internal error) | Write the type out |
| [Closures](/docs/language/closures/) and lambdas (`fn () { ... }` as a value) | Compile, with every capture mode (by copy, `\|*\|`, `\|*x\|`, `\|const *x\|`, mixed, `\|\|`), stored in a `fn` variable or field, passed, returned and nested. One that captures nothing can be passed where a C function pointer is expected. Not yet: generic closures (`fn <T>(x: T)`) are rejected with [SC116E](/docs/language/diagnostics/#sc116e-a-feature-is-not-yet-supported); a closure's default parameter values are dropped, so a call must pass every argument; `async` on a closure is ignored (it runs as a plain closure). Copying a closure that holds a moved-in MOVE value stops the program, and so does passing a closure that captures where a C function pointer is expected | Use a named generic function; pass every argument; capture a MOVE value by pointer (`\|*x\|`) when the closure is copied |
| [Nullables](/docs/language/nullables/) (`T?`, `null`, `x?`, `== null`, `??`, `?.`, `?->`, `===`, `unwrap!()`, `match` on a `T?`) | `T?` and `null` compile: a `T?` is `::builtin::Nullable<T>` in C++, and a value or `null` converts into one anywhere a `T?` is expected (including `*T?`, a nullable pointer `(*T)?`, and nested `(T?)?`). `var x? = e`, the null test `x?`, `== null` / `!= null`, `??`, `?.`, `?->`, `===`, `unwrap!()`, a `match` on a `T?` and the checked downcast `p as *D?` compile. [Narrowing](/docs/language/nullables/#narrowing) works: a checked nullable reads as its `T`, through conditions, early exits, loops, `match` arms, `@inout` and mutable-`self` calls, pointers and closures, and an unchecked read is a compile error. Not yet: `bool?` is not one byte (a `bool` has no spare value the compiler uses yet); `T? -> U?` between different inner types fails in the C++ compiler; a nullable reached through `->` or a subscript is not narrowed by a check; a checked downcast from a nullable pointer (`maybe_animal as *Dog?`) is rejected; in a generic function, `===` on a `T?` compares addresses when `T` turns out to be a pointer (only a written `*T?` compares what it points to) | Copy a nullable reached through `->` or a subscript to a local before checking it; test a nullable pointer before downcasting it (`if a? { a as *Dog? }`) |

## Checked by C++, Not by Kairo

Access control is enforced, but the error comes from the C++ compiler at build time rather than as a Kairo diagnostic. The C++ step is also stricter than Kairo: a free function in the class's own module that reads a `priv` member is rejected, although [visibility](/docs/language/classes/#visibility) is module-wide and allows it. This covers `priv` constructors and assignments to a `const` variable (`const x: i32? = 42` then `x = null`, or to a `static const` / `thread const`): `--type-check-only` does not report the last. One case is caught by neither: an assignment to a top-level `const` of a [script](/docs/language/modules/#scripts) whose initializer is not a constant (`const LIMIT = load()` then `LIMIT = 6`) compiles and runs.

## Not Diagnosed

Passing a slice literal to a function that **stores** the slice is not caught. The literal's storage ends with the statement, so the stored slice dangles. This becomes an error when [Tether](/docs/language/tether/) lands; until then, pass a `var` or a `[T]` to any function that keeps what it is given. See [Primitives](/docs/language/collections/#how-long-a-slice-literals-storage-lives).

Assigning to a `const` binding introduced by a `match` pattern (`case .Error(const message)`) is not reported. See [Enums](/docs/language/enums-adt/#destructuring-with-match).

Initializing or assigning a safe pointer `*T` with `&null` (`var p: *i32 = &null`) is not reported, although `*T` is never null by design. Use a nullable pointer `*T?` for a pointer that may be absent. See [Pointers and nullability](/docs/language/nullables/#pointers-and-nullability).

Declaring `var x: T` with no initializer in a generic body is not reported when no bound requires a default constructor. See [Generic Bodies](/docs/language/interfaces/#generic-bodies).

Three [`extend`](/docs/language/extends/) rules are not diagnosed yet:

- A plain `extend` outside the type's file, or an `extend ... impl` in neither the type's nor the interface's file, is accepted. See [Same-File Restriction](/docs/language/extends/#same-file-restriction).
- Calling an extension member whose bounds the type arguments do not satisfy is not reported at the call site. See [Generic Extends](/docs/language/extends/#generic-extends).
- An `extend ... impl` that is missing interface methods is not reported at the `extend` declaration. See [Interface Conformance](/docs/language/extends/#interface-conformance).

A [generator](/docs/language/functions-generators/#generator-lifetimes) that outlives the object it was created from, or an `@inout` argument it was given, is not caught; it dangles. This becomes an error when [Tether](/docs/language/tether/) covers generators. Until then, do not keep a generator longer than the object it came from.

A [closure](/docs/language/closures/#tether-and-lifetime-safety) that captures a local by pointer (`|*x|`, `|*|`) and outlives it, by being returned or stored, is not caught; the pointer dangles. This becomes an error when [Tether](/docs/language/tether/) lands. Until then, capture by copy in a closure that leaves its scope.

## Not in This Release

- [Tether](/docs/language/tether/), Kairo's memory-safety system, is not part of the alpha. Using a moved-from value is already a compile error; the rest of Tether's checks come later.
- Some generic code is checked less strictly than it will be in 1.0.
- The standard library is minimal: printing goes through `std::io::println`.
- A program cannot read its command-line arguments yet: `main` takes no parameters, and `sys::args` (for scripts and programs alike) is planned.
- Objective-C headers cannot be imported with `ffi` yet; C and C++ headers can. Plain C and Objective-C files cannot `#include` a `.k` file yet; C++ and Objective-C++ files can.

---

## Language Gaps

- A Kairo `string` cannot be passed to a C `const char*` parameter; `string.c_str()` is planned. See [C & C++ Interoperability](/docs/language/c-cpp-calling/#strings-and-const-char).
- Evaluation order is left to right for arguments, except for calls returning a C++ reference or class object and for primitive operators whose two operands both have side effects. See [Operators](/docs/language/operators/#evaluation-order).
