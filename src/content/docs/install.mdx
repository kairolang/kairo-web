# Installation

Kairo ships as a **prebuilt package** for each supported target. Download one, extract it and add its `bin` directory to your `PATH`. Most users want this.

The compiler, `kairo`, is written in Kairo and compiles itself. A package holds everything it needs: `kairo` and `kcc`, the pinned Clang and lld it drives, `compiler-rt`, and the `builtin` and `std` libraries. You do not need a system C or C++ toolchain.

---

## Prebuilt Packages

Download the package for your platform from the [release page](https://github.com/kairolang/kairo/releases), extract it, and add the `bin` directory to your `PATH`.

| Platform | Architecture | File |
|---|---|---|
| Linux (static, musl) | x86_64 | `kairo-<version>-x86_64-linux-musl.tar.xz` |
| Linux (static, musl) | i686 | `kairo-<version>-i686-linux-musl.tar.xz` |
| Linux (static, musl) | aarch64 | `kairo-<version>-aarch64-linux-musl.tar.xz` |
| Linux (static, musl) | armv7 | `kairo-<version>-armv7-linux-musl.tar.xz` |
| Linux (static, musl) | riscv64 | `kairo-<version>-riscv64-linux-musl.tar.xz` |
| macOS 10.15 or newer | x86_64 | `kairo-<version>-x86_64-apple-macosx10.15.zip` |
| macOS 11 or newer | arm64 (Apple Silicon) | `kairo-<version>-arm64-apple-macosx11.0.zip` |
| Windows (MinGW) | x86_64 | `kairo-<version>-x86_64-windows-gnu.zip` |
| Windows (MinGW) | i686 | `kairo-<version>-i686-windows-gnu.zip` |
| Windows (MinGW) | aarch64 | `kairo-<version>-aarch64-windows-gnu.zip` |
| Windows (MinGW) | armv7 | `kairo-<version>-armv7-windows-gnu.zip` |
| FreeBSD | x86_64 | `kairo-<version>-x86_64-unknown-freebsd.tar.xz` |
| FreeBSD | aarch64 | `kairo-<version>-aarch64-unknown-freebsd.tar.xz` |
| NetBSD | x86_64 | `kairo-<version>-x86_64-unknown-netbsd.tar.xz` |

The compiler bundles an LLVM 22 toolchain (Clang, lld, compiler-rt) built from Kairo's [patched fork](https://github.com/kairolang/llvm-project).

> [!NOTE]
> The test suite runs on x86_64 Linux only. The other packages are built and cross-checked from it, but they have not been through the suite on their own platforms.

### Sysroots

The packages do not include the target sysroots (C library, headers and runtime libraries). They come in one separate archive, `kairo-<version>-sysroots.tar.xz`, that holds the sysroot for every target the compiler can build for. Extract it inside the package, so that `sysroot/` sits next to `bin/`:

```bash
tar xf kairo-<version>-x86_64-linux-musl.tar.xz
tar xf kairo-<version>-sysroots.tar.xz -C kairo-<version>-x86_64-linux-musl
```

Without a sysroot the compiler warns (`P008W`) and names the flag to pass, `--sysroot=<dir>`, or `--freestanding` to compile without system headers and libraries. The sysroots take about 5 GB unpacked; you can delete the ones for targets you never build for.

Every package can build for every sysroot target: the compiler you download for your machine is also the cross-compiler. See [kairo, kcc & Cross-compilation](/docs/language/c-cpp-toolchain/).

### System requirements

- **Linux:** any x86_64, i686, aarch64, armv7 or riscv64 distribution. The compiler is statically linked against musl and needs no system libc, libc++ or libunwind.
- **macOS:** 10.15 (Catalina) or newer on Intel, 11 (Big Sur) or newer on Apple Silicon.
- **Windows:** the compiler is built with MinGW and has no Visual C++ Redistributable dependency.
- **FreeBSD, NetBSD:** x86_64 (and aarch64 on FreeBSD).

> [!CAUTION]
> On macOS, a downloaded binary is quarantined and Gatekeeper will refuse to run it ("cannot verify this app is free of malware"), because the release binaries are not yet notarized. Clear the quarantine flag on the extracted package before first run:
>
> ```bash
> xattr -dr com.apple.quarantine ./kairo-<version>-arm64-apple-macosx11.0
> ```
>
> This applies only to packages downloaded from the release page; builds from source are unaffected.

### Add to PATH

**Linux / macOS:**

```bash
export PATH="$PATH:/path/to/kairo-<version>-<triple>/bin"
```

Add that line to your `~/.bashrc` or `~/.zshrc` to make it permanent.

**Windows (PowerShell):**

```powershell
$env:Path += ";C:\path\to\kairo-<version>-x86_64-windows-gnu\bin"
```

This sets `PATH` for the current session. To persist it across sessions:

```powershell
[Environment]::SetEnvironmentVariable("Path", "$env:Path;C:\path\to\kairo-<version>-x86_64-windows-gnu\bin", "User")
```

For Command Prompt, add the path via System Properties -> Environment Variables.

### Validate

Create a file called `test.k`:

```kairo
import std::io

fn main() -> i32 {
    var x = 5
    var y = 10
    io::println(f"Hello, world! Sum of {x} and {y} is {x + y}")
    return 0
}
```

Compile and run it:

```bash
kairo test.k -o test
./test
```

```
Hello, world! Sum of 5 and 10 is 15
```

Without `-o`, the executable is written to `a.out`.

The executable targets the machine you compile on. On Linux that is the host's glibc triple (`x86_64-linux-gnu`), which links dynamically against the system libc. For a static executable, pass `--target=x86_64-linux-musl`. To build for another platform, pass its triple with `--target`.

## Building from Source

Build from source if you need unreleased changes or are developing Kairo itself. The compiler is written in Kairo, so building it needs an existing Kairo compiler: a prebuilt package from above.

### Requirements

- A prebuilt Kairo package, as the bootstrap compiler
- **git** and **Python 3**
- Disk space and time for the patched LLVM, which is built once and reused

You do not need a system Clang or xmake. The earlier C++ bootstrap compiler, Stage 0, is retired.

### Build

```bash
git clone https://github.com/kairolang/kairo/
cd kairo
git submodule update --init --recursive   # pulls the patched LLVM (large download)
python3 build.py --release --kairo /path/to/kairo-<version>-<triple>/bin/kairo kairo kcc
```

The first build also builds the patched LLVM (once; later builds reuse it). `--kairo` names the bootstrap compiler; it can be left out when that `kairo` is on your `PATH`, and later builds use the last one they produced.

`build.py` builds the compiler with the bootstrap compiler, rebuilds it with the result (so the final compiler is built by itself), and stages a self-contained package in `build/<triple>/release/`, where `<triple>` is your host's static musl triple (`x86_64-linux-musl` on x86-64 Linux): `bin/` holds `kairo` and `kcc` beside the bundled `clang` and `lld`, and `lib/` holds the clang resource directory, the `builtin`, `std` and `rt` libraries and every shared library the binaries need. The compiler finds all of it from its own location, so it runs with no flags:

```bash
build/x86_64-linux-musl/release/bin/kairo main.k -o main
```

`--debug` builds an unoptimized compiler that is quicker to rebuild. `--resource-dir`, `--builtins-dir`, `--std-dir` and `--sysroot` override what the compiler finds. If one of them cannot be found the compiler warns, naming the path it searched and the flag to pass. Not having a sysroot is a warning too, unless you pass `--freestanding`.

`Scripts/package_release.py` turns a built tree into a release archive.

## VSCode Extension

VSCode is currently the only editor with LSP support and `.k` syntax highlighting. The language server ships as part of the compiler, so there is nothing extra to run: the extension only needs to locate `kairo`.

### Install

Pick whichever is easiest:

- **Marketplace:** install from the [Kairo extension page](https://marketplace.visualstudio.com/items?itemName=KSF.kairo).
- **Prebuilt VSIX:** download the latest `.vsix` from [kairo-lsp](https://github.com/kairolang/kairo-lsp/) (e.g. `kairo-0.5.5.vsix`), then in VSCode: **Extensions** -> **...** -> **Install from VSIX...**
- **Build from source:**

```bash
git clone https://github.com/kairolang/kairo-lsp/
cd kairo-lsp
npm install
npm run build --omit=dev
npx @vscode/vsce package
```

This produces a `.vsix` you install the same way.

### Configure

If `kairo` is on your `PATH`, the extension finds it automatically, no configuration needed. Otherwise set `kairo.path` in your VSCode `settings.json` to the compiler's location. If it cannot find the compiler, you get a single "path not set" warning.

### Debugging

- **Run Kairo File** - runs and attaches the debugger
- **Run Kairo File with Args** - prompts for comma-separated args (e.g. `arg1,arg2,arg3`)

Both work with `fn main()` or `fn Test()` entry points.

> [!WARNING]
> With `fn Test()`, VSCode redirects to a temporary file during debugging. Breakpoints work, but
> **edits are not saved back to your original file**. Re-running the debugger resets everything. Use `fn main()` for active development.

## Troubleshooting

**macOS: "cannot verify this app is free of malware" when running a downloaded package.** Release binaries are not yet notarized. Clear the quarantine flag:

```bash
xattr -dr com.apple.quarantine ./kairo-<version>-arm64-apple-macosx11.0
```

This does not affect source builds, only packages downloaded from the release page.

**`warning [P008W]: no sysroot found for target ...`.** The sysroots archive is not extracted next to `bin/`. See [Sysroots](#sysroots), or pass `--sysroot=<dir>`.
